# Deployment guide

**Status: not verified.** This project has not been deployed, built with `next build`, or run against a real database in the environment that produced this repository. The steps below are derived from the code and the documented commands. Each one must be executed and confirmed by the operator. See `docs/STATUS.md` for what has and has not been run.

## Target

- Next.js (App Router) on Vercel, or any Node.js host that runs `next build` and `next start`.
- PostgreSQL 14 or later, managed (for example Neon, Supabase, Vercel Postgres, RDS). Migrations are applied by a separate step, not at application start.
- Scheduled synchronization by a cron job, a hosted scheduler, or a worker, calling `POST /api/sync` with the worker secret or running `npm run sync:run`.

## 1. Provision the database

1. Create a PostgreSQL database and a dedicated role that has access to it only.
2. Put the connection string in `DATABASE_URL`, with `sslmode=require` for managed hosts.
3. Apply the migrations from a trusted machine, never from a request handler:

   ```bash
   npm ci
   npx prisma migrate deploy
   npx prisma migrate status    # must report "Database schema is up to date!"
   ```

   The first run requires the initial migration, `prisma/migrations/20261118000000_init`. It is generated by `bash scripts/generate-init-migration.sh` and is **not committed in this repository**. Generate it and commit it before deploying. The migration checker, `npm run verify:schema`, fails until it exists.

## 2. Configure Google OAuth

Create two OAuth clients in Google Cloud Console (type: Web application).

| Client | Used for | Authorized redirect URI |
| --- | --- | --- |
| Sign-in | `AUTH_GOOGLE_ID`, `AUTH_GOOGLE_SECRET` | `https://<your-domain>/api/auth/callback/google` |
| Gmail | `GOOGLE_GMAIL_CLIENT_ID`, `GOOGLE_GMAIL_CLIENT_SECRET` | `https://<your-domain>/api/gmail/callback` |

- Set `GOOGLE_GMAIL_REDIRECT_URI` to the Gmail callback URI above.
- Enable the Gmail API. The Gmail client requests only `https://www.googleapis.com/auth/gmail.readonly`.
- Gmail access is a **restricted scope**. Before public use, Google's OAuth verification must be completed and a third-party security assessment is required. Until then, the consent screen is limited to the test users you add. Refresh tokens for apps in "Testing" expire after seven days. **Verification has not been completed for this project.**

## 3. Environment variables

Set every variable from `.env.example` in the host's secret store, not in the repository. Required in production:

- `DATABASE_URL`, `AUTH_SECRET`, `AUTH_URL` (the public origin, `https://...`)
- `AUTH_GOOGLE_ID`, `AUTH_GOOGLE_SECRET`
- `GOOGLE_GMAIL_CLIENT_ID`, `GOOGLE_GMAIL_CLIENT_SECRET`, `GOOGLE_GMAIL_REDIRECT_URI`
- `TOKEN_ENCRYPTION_KEY` (32 random bytes, base64). Losing or changing it makes stored Gmail tokens unreadable.
- `SYNC_SECRET` if the scheduled worker calls `/api/sync`

Set `AUTH_TRUST_HOST=false` unless the host sets the Host header itself and `AUTH_URL` is unset. Generate secrets with:

```bash
openssl rand -base64 32    # AUTH_SECRET, TOKEN_ENCRYPTION_KEY
openssl rand -hex 32       # SYNC_SECRET
```

## 4. AI provider

AI is optional. The application works with `AI_PROVIDER=none`.

- **Ollama (local):** run Ollama on a host you control and set `OLLAMA_BASE_URL` to it. Email content is sent to that host. Do not point this at a third-party server unless you accept that.
- **Gemini (cloud):** set `GEMINI_API_KEY`, `GEMINI_TIER=paid` **only after billing is enabled on the key's project**, and `AI_PROVIDER=gemini`. The user must also consent in Settings. With `GEMINI_TIER=free`, the application refuses to send email content to Gemini. The setting is an attestation by the operator; the application cannot verify billing.

## 5. Build and start

```bash
npm ci
npm run build          # runs prisma generate, then next build
npm run start
```

Vercel runs the build automatically. Confirm that the build step includes `prisma generate` (the `build` script does this) and that the migration step above runs separately.

## 6. Scheduled synchronization

Manual sync works from the UI. For mail to stay current, schedule one of:

- A cron job on a host you control: `npm run sync:run` (needs database access and the environment).
- An external scheduler calling `POST https://<domain>/api/sync` with header `Authorization: Bearer <SYNC_SECRET>`.

**Known limitation:** the first sync after connecting Gmail runs inside the OAuth callback request. A large mailbox can exceed a serverless function's time limit. If the first sync reports a failure, use Sync now or the scheduled job; the connection is kept.

## 7. Post-deploy verification

1. `GET /` loads without console errors and the security headers are present (`Content-Security-Policy`, `Strict-Transport-Security`, `X-Frame-Options: DENY`).
2. Sign in with a Google account that is a listed test user. Sign out. Confirm `/inbox` redirects to `/login` while signed out.
3. Connect Gmail. Confirm the callback banner reports the connection and the first sync result separately.
4. Run Sync now. Confirm the result matches the account state.
5. Export your data and confirm the JSON contains no tokens.
6. Disconnect Gmail, confirm local mail is removed, then delete the test account.

Record each result in `docs/STATUS.md`. Do not treat this checklist as passed until it has been executed.

## Troubleshooting

- **`no initial migration creates every model table`**: the initial migration is missing. Run `bash scripts/generate-init-migration.sh`, commit it, then `npx prisma migrate deploy`.
- **`redirect_uri_mismatch` from Google**: the redirect URI in Google Cloud does not match `AUTH_URL` or `GOOGLE_GMAIL_REDIRECT_URI` exactly, including scheme and trailing slash.
- **`Connection is NEEDS_REAUTH`**: Google rejected the stored refresh token (revoked, expired in Testing mode, or the key changed). Use Reconnect Gmail.
- **Gmail stays "not synced"**: the first sync failed or timed out. The error is shown on the Gmail page. Use Sync now, or the scheduled job.
- **AI shows "not configured" or "free tier"**: see section 4. Email content is never sent to the Gemini free tier.
- **`Invalid environment configuration`**: a variable has an invalid format (for example, `GOOGLE_GMAIL_REDIRECT_URI` must be a full URL). The message names the variable.
